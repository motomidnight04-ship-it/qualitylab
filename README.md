## Задание 13. Профилирование
- **Просят:** найти утечку памяти и «тяжёлые» места, показать метрики до и после.
- **Делаем:**
  1) **Утечка.** Запускаем приложение (разрешите уведомления для LeakCanary). Открываем экран «Memory leak», возвращаемся назад, ждём ~10 секунд. Появится уведомление об утечке — нажимаем, делаем скриншот цепочки ссылок (виновник: `LeakHolder.lastActivity`). Исправляем: в `LeakActivity.java` удаляем строку `LeakHolder.lastActivity = this;` и повторяем проверку.
  2) **StrictMode.** В Logcat пишем в поиске `StrictMode` и перезапускаем приложение: видны нарушения. Исправляем в `MainActivity.java`: `.commit()` заменить на `.apply()`. Перезапускаем и сравниваем.
  3) **Profiler.** View → Tool Windows → Profiler → Start profiling → Memory: нажимаем «Capture heap dump» до и после исправления; CPU: запись при открытии Tasks → «+50 demo».
- **Получится:** до — уведомление об утечке и строки StrictMode; после — их нет. В отчёт: таблица «до и после» (из `docs/QUALITY_REPORT.md`) и скриншоты.

## Задание 14. Скорость и облачное тестирование
- **Просят:** измерить скорость запуска и плавность, запустить тесты на разных устройствах в облаке.
- **Делаем:** подключаем телефон (или запускаем эмулятор), в Terminal: `.\gradlew.bat :benchmark:connectedBenchmarkAndroidTest`. Либо в Project открываем `benchmark/src/main/java/.../StartupBenchmark.kt` и запускаем зелёным треугольником у класса. В конце в окне Run смотрим строки `timeToInitialDisplayMs` (время холодного старта) и `frameDurationCpuMs` (плавность прокрутки).
  Firebase Test Lab: нужен аккаунт Google. Заходим на console.firebase.google.com → создаём проект → Test Lab → Run a test → загружаем APK (`app/build/outputs/apk/debug/app-debug.apk`, появится после Build → Build APK) → выбираем 2–3 устройства. Если Firebase недоступен, задание допускает аналог: запуск на нескольких своих эмуляторах.
- **Получится:** числа времени старта и кадров, а в Firebase — отчёт с видео и логами по каждому устройству.

## Задание 15. CI и итоговый отчёт
- **Просят:** чтобы проверки запускались автоматически на GitHub и был итоговый отчёт.
- **Делаем:** VCS → Create Git Repository → выбираем папку проекта; затем Git → Commit (отметить все файлы) → Git → GitHub → Share Project on GitHub (войти в аккаунт). На сайте GitHub открываем репозиторий → вкладка **Actions** → запуск «Android CI». Внизу страницы запуска — раздел Artifacts с HTML-отчётами. Потом заполняем `docs/QUALITY_REPORT.md` (числа берём из заданий 12–14 и этих замеров).
- **Получится:** зелёная галочка у запуска, ссылка на репозиторий для отчёта, заполненный отчёт о качестве.
